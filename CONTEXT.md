### ЭТАП 12. ЗАЩИТА ОТ ПЕРЕПРОДАЖИ (Текущая реализация)

**Как работает защита:**
1. В `config.py` есть список `ALLOWED_LICENSE_KEYS` — сюда вы вписываете ключи, которые выдаете клиентам.
2. В `.env` клиента (или в переменных хостинга) должен быть `LICENSE_KEY`, совпадающий с одним из ключей в списке.
3. При запуске `main.py` проверяет: если `LICENSE_KEY` нет в списке — бот не запускается.
4. Дополнительно можно включить проверку `BOT_TOKEN` — в `ALLOWED_BOT_TOKENS` вписываете токены клиентов. Если токен не в списке — бот не запускается.

**Как выдавать клиенту:**
1. Клиент создает бота в BotFather, получает токен (например, `1234567890:AAH...`).
2. Клиент присылает вам токен.
3. Вы добавляете токен в `ALLOWED_BOT_TOKENS` в `config.py` (или в отдельный файл, если клиентов много).
4. Вы генерируете уникальный `LICENSE_KEY` для клиента (например, `client_ivan_2026`).
5. Вы добавляете этот ключ в `ALLOWED_LICENSE_KEYS` в `config.py`.
6. Вы отправляете клиенту архив с обновленным `config.py` и говорите: «Вставь в `.env` свой `LICENSE_KEY` и `BOT_TOKEN`».
7. Клиент запускает бота. Если ключ и токен верные — бот работает.

**Ограничения:**
- Клиент может открыть `config.py` и добавить свой ключ/токен в список (обойти защиту). Для серьезной защиты нужна обфускация (PyArmor) — отложено на потом.
- Если клиентов много, список токенов/ключей становится большим. Можно вынести в отдельный файл `allowed_keys.txt` и читать его.

**Следующий шаг:** Дальнейшие доработки (поддержка, менеджеры, клиенты) — уже реализованы. При необходимости — обфускация и финальная проверка.
📖 Подробная инструкция: как добавлять токен и ключи
1. Где хранятся ключи и токены

Все ключи хранятся в файле config.py в двух списках:
python

ALLOWED_LICENSE_KEYS = [
    "universalshop_demo_2026",   # ваш мастер-ключ
    "client_ivan_2026",          # ключ клиента Ивана
    "client_maria_2026",         # ключ клиента Марии
]

ALLOWED_BOT_TOKENS = [
    "1234567890:AAH...",         # токен бота Ивана
    "0987654321:BBK...",         # токен бота Марии
]

2. Как добавить нового клиента

Шаг 1. Клиент создает бота в BotFather и присылает вам токен (например, 5555555555:CCL...).

Шаг 2. Откройте config.py и добавьте:

    В ALLOWED_LICENSE_KEYS — новый уникальный ключ (например, "client_petr_2026").

    В ALLOWED_BOT_TOKENS — токен клиента (например, "5555555555:CCL...").

Шаг 3. Сохраните config.py и отправьте клиенту архив с проектом.

Шаг 4. Скажите клиенту: «В файле .env (или в переменных хостинга) укажи:

    BOT_TOKEN=5555555555:CCL... (его токен)

    LICENSE_KEY=client_petr_2026 (его ключ)

    ADMIN_ID=его_telegram_id

    DATABASE_URL=его_строка_подключения»

Шаг 5. Клиент запускает бота. Если ключ и токен совпадают с теми, что в config.py, — бот работает.
3. Если клиентов много

Список в config.py станет огромным. Можно вынести ключи в отдельный файл allowed_keys.txt (в корне проекта):
text

universalshop_demo_2026
client_ivan_2026
client_maria_2026

И в config.py читать его:
python

import os

def load_allowed_keys():
    if os.path.exists("allowed_keys.txt"):
        with open("allowed_keys.txt", "r", encoding="utf-8") as f:
            return [line.strip() for line in f if line.strip()]
    return []

ALLOWED_LICENSE_KEYS = load_allowed_keys()

Тогда вам не нужно менять config.py для каждого клиента — просто дописываете строку в allowed_keys.txt.
4. Что делать, если клиент сменил токен

Если клиент пересоздал бота (например, старый заблокировали), он присылает вам новый токен. Вы заменяете старый токен в ALLOWED_BOT_TOKENS на новый. Клиент обновляет .env и перезапускает бота.
5. Что делать, если клиент продал архив другому

Другой человек получит код, но:

    Его токен не будет в ALLOWED_BOT_TOKENS (если вы не добавили).

    Его ключ не будет в ALLOWED_LICENSE_KEYS.

Бот не запустится, пока он не обратится к вам за ключом. Если он обратится — вы можете продать ему лицензию (добавить его токен и ключ в списки).
6. Что делать, если клиент «взломал» защиту

Он может открыть config.py и добавить свой ключ/токен. Чтобы это предотвратить:

    PyArmor (обфускация) — код станет нечитаемым.

    Привязка к домену/серверу — бот проверяет IP или домен, на котором запущен.

    Удаленная проверка — бот стучится на ваш сервер за разрешением.
